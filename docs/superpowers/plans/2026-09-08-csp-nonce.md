**Goal:** `script-src` verliert `'unsafe-inline'` zugunsten einer Nonce, die pro Request erzeugt und sowohl im CSP-Header als auch an Next.js' eigenen Inline-Bootstrap weitergegeben wird.

**Architektur:** Eine neue `middleware.ts` erzeugt pro Request eine Zufalls-Nonce, reicht sie über einen Request-Header an Server Components weiter und setzt den CSP-Header direkt (statt wie bisher statisch über `next.config.ts` → `headers()`). `content-security-policy.ts` bekommt einen `nonce`-Parameter statt der festen `'unsafe-inline'`-Direktive.

**Tech Stack:** Next.js Middleware, Web Crypto (`crypto.randomUUID()` oder `crypto.getRandomValues`), Playwright (E2E-Wache aus `tests/fixtures.ts`).

**Spec:** Begründung für den bisherigen Aufschub in `docs/superpowers/plans/2026-09-06-tier2-security.md:340` (siehe Recherche unten), aktueller Stand in `apps/web/src/lib/content-security-policy.ts` und `apps/web/next.config.ts:76-78`.

## Global Constraints

- `'unsafe-eval'` bleibt ausschliesslich im Entwicklungsserver (`allowEval`, unverändert) — diese Task betrifft nur `'unsafe-inline'`.
- CSP bleibt erzwingend (nicht zurück zu Report-Only) — Umstellung 2026-09-07 war ein abgeschlossener, bewusster Schritt.
- `report-uri`/`report-to` bleiben unverändert bestehen.
- Kein `any`, `strict: true` (AGENTS.md §5).

- [ ] **Step 4: Minimale Implementierung**

`apps/web/src/lib/content-security-policy.ts`:

```ts
export interface ContentSecurityPolicyOptions {
  readonly apiOrigin: string;
  readonly reportUri: string;
  readonly allowEval: boolean;
  /**
   * Pro Request neu erzeugt (siehe `proxy.ts`). Ersetzt `'unsafe-inline'`
   * fuer `script-src` -- Next.js' eigener Inline-Bootstrap traegt dieselbe
   * Nonce, sobald sie im CSP-Response-Header steht (siehe Task 1, Ergebnis 1).
   */
  readonly nonce: string;
}

export function buildContentSecurityPolicy({
  allowEval,
  apiOrigin,
  nonce,
  reportUri,
}: ContentSecurityPolicyOptions): string {
  const websocketOrigin = apiOrigin.replace(/^http/u, "ws");
  const scriptSource = allowEval
    ? `script-src 'self' 'nonce-${nonce}' 'unsafe-eval'`
    : `script-src 'self' 'nonce-${nonce}'`;

  return [
    "default-src 'self'",
    "base-uri 'self'",
    "object-src 'none'",
    "frame-ancestors 'none'",
    "form-action 'self'",
    scriptSource,
    "style-src 'self' 'unsafe-inline'",
    "img-src 'self' data:",
    "font-src 'self' data:",
    `connect-src 'self' ${apiOrigin} ${websocketOrigin}`,
    `report-uri ${reportUri}`,
    "report-to csp-endpoint",
  ].join("; ");
}
```

(`style-src` behält `'unsafe-inline'` — Tailwind/inline styles sind nicht Teil dieser Task; nur `script-src` ändert sich.)

**Interfaces:**
- Consumes: `buildContentSecurityPolicy` (Task 2, neue Signatur mit `nonce`).
- Produces: Request-Header `x-nonce` für nachgelagerte Server Components.

**Kontext:** `next.config.ts:76-78` setzt aktuell alle Security-Header statisch für `/:path*`. Eine Nonce muss pro Request neu sein — das kann `headers()` in `next.config.ts` nicht (statisch je Pfad, nicht je Anfrage), deshalb übernimmt `proxy.ts` künftig **nur** den `Content-Security-Policy`-Header, alle anderen (HSTS, X-Content-Type-Options, etc.) bleiben unverändert in `next.config.ts`.

- [ ] **Step 1: `proxy.ts` erstellen**

Next.js liest die Nonce selbst aus dem CSP-Response-Header für seinen eigenen Bootstrap (Task 1, Ergebnis 1 — bestätigt). Datei- und Funktionsname folgen der aktuellen, nicht-deprecateten Konvention dieser Next.js-Version (Task 1, Ergebnis 2):

```ts
// apps/web/src/proxy.ts
import { NextResponse, type NextRequest } from "next/server";

import { buildContentSecurityPolicy } from "@/lib/content-security-policy";

const configuredApiUrl = process.env.NEXT_PUBLIC_API_URL;
const apiOrigin = configuredApiUrl === undefined ? "http://localhost:3001" : new URL(configuredApiUrl).origin;
const cspReportUri = `${apiOrigin}/api/v1/csp-reports`;

export function proxy(request: NextRequest): NextResponse {
  const nonce = crypto.randomUUID();
  const contentSecurityPolicy = buildContentSecurityPolicy({
    apiOrigin,
    reportUri: cspReportUri,
    allowEval: process.env.NODE_ENV !== "production",
    nonce,
  });

  const requestHeaders = new Headers(request.headers);
  requestHeaders.set("x-nonce", nonce);

  const response = NextResponse.next({ request: { headers: requestHeaders } });
  response.headers.set("Content-Security-Policy", contentSecurityPolicy);
  response.headers.set("Reporting-Endpoints", `csp-endpoint="${cspReportUri}"`);
  return response;
}

export const config = {
  // Statische Assets und interne Next.js-Pfade brauchen keine Nonce.
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
};
```
