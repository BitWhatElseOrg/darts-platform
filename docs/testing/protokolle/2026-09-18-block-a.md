## Abweichung von der Aufgabenvorlage (kein Befund, sondern Testfehler)

Der Beispielcode in der Aufgabe erwartete für erfolgreiche
`POST …/visits`- und `POST …/undo`-Aufrufe HTTP 200. Tatsächlich liefert die
API 201, weil `matches.controller.ts` für diese Routen kein `@HttpCode()`
setzt und NestJS für `@Post()` standardmässig 201 zurückgibt. Das ist der
dokumentierte Nest-Standard, kein Abweichen vom Fehlerformat oder von den
Nebenläufigkeits-Invarianten. Die Testerwartung wurde entsprechend auf 201
korrigiert; die eigentlichen Prüfungen (genau ein Erfolg + ein Konflikt,
Version, Visit-Anzahl, konsistenter Endzustand) blieben unverändert.

Zweite Korrektur: Die Vorlage nahm an, der aktive Spieler wechsle strikt nach
`playerIds[version % 2]`. Für A6 wird der aktive Spieler stattdessen aus dem
Zustand gelesen (`participants[].isActive`), wie in der Aufgabenbeschreibung
vorgesehen; ein `NOT_ACTIVE_PLAYER`-Fehler ist dabei nicht aufgetreten, die
Zuordnung stimmte in diesem Lauf mit der Annahme der Vorlage überein.
