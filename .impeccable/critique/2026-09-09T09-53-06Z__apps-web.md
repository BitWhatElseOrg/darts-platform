## Design Specificity Verdict

**LLM assessment**: Split personality. The authenticated command-centre surfaces (`command-centre.tsx`, `board-wedge.tsx`, `encounter-command-centre.tsx`, `setup-sheet.tsx`, `player-profile.tsx`) are genuinely authored for a dart platform: Sektorenring tokens, the `Score`/`StateTag`/`BoardPlate`/`Wedge` vocabulary, tabular numerals, Reglement clause numbers baked into UI copy, keyboard shortcuts keyed to ring numbers. This could not be relabeled into a generic SaaS dashboard without real rework. But the surfaces that matter most operationally — the live match scoreboard (`components/match/*`), every public spectator/TV/board view (`live-tournament.tsx`), the entry page's health panel, and the offline page — abandon the design system for raw `slate-900`/`emerald-500`/`amber-300`/`rose-300` Tailwind that could belong to any admin tool. The specificity verdict depends entirely on which half of the app you look at, and the "generic" half happens to be exactly where the two primary personas spend their moment of use.

**Deterministic scan**: `detect.mjs --json apps/web/src` exited 2 with 11 findings, all one rule (`gray-on-color`, a text/background contrast check): 10 of the 11 are `text-slate-950`/`text-slate-200`/`text-slate-400` set against `bg-emerald-500`, concentrated in `checkout-dialog.tsx:108`, `dart-keypad.tsx:111,121`, `round-keypad.tsx:142`, `scoreboard-settings-dialog.tsx:45(×2),89`, `scoreboard-sides.tsx:51,69`, `visit-confirmation.tsx:83`; the 11th is `text-slate-950 on bg-amber-500` in `members-route.tsx:306`. This is independent, mechanical confirmation of the LLM finding above: every one of these is a raw off-token color the design system explicitly forbids (no third accent hue; signal colors only in their contrast-correct "lit"/"filled" pair), and the detector proves several of them are also failing contrast, not just off-brand. No false positives — all 11 sit in real component source, none in tests or generated files. The detector has no rule for the two deviations already tracked in DESIGN.md (duplicate `--color-sisal-*` values, `sisal-*`/`wedge-*` naming debt), so their absence from this scan is expected, not a clean bill of health on those points.

**Visual overlays**: No browser-automation tool is exposed in this session, so no live `[Human]`-tab overlay could be produced. This is a factual environment limitation, not a finding — treat the scan and code review above as the evidence for this run; a future run with browser tooling available would add live contrast/console overlays on top of it.

## Overall Impression

The parts of this product built *as* the Sektorenring system are unusually rigorous — offline/idempotency/version-conflict handling is exposed truthfully in the UI, not just correct in the API, and the domain rulebook is legible on screen, not buried in code comments. But the system stops at the command-centre's edge: the actual scoring screen a board scorer stares at for an entire match, and every public-facing view, were built on a separate track and never reconciled with the design system — reintroducing the exact "third accent hue" and color-only signaling the system's own rules exist to prevent. The single biggest opportunity is a reconciliation pass on `components/match/*` and `components/live/*`: pulling them onto `Score`, `StateTag`, `Wedge` and the two-signal palette would fix the P0 below essentially for free, because the correct pattern already exists and is already used correctly elsewhere in the same codebase.

## What's Working

1. **Offline/idempotency/version-conflict engineering is exposed truthfully in the UI.** Read/write queue errors are kept separate, replay versioning is chained, discard-vs-retry is distinct, all in plain-language copy (`command-centre.tsx`, `use-match-scoring.ts`). Unusually rigorous for a feature this easy to fake.
2. **The Sektorenring vocabulary, where used, is a real design language, not a skin.** `Score`'s `display`/`lead` sizing exists specifically to encode whose turn it is; `StateTag` hard-codes color+mark+word together so it can't regress to color-only by accident; `BoardPlate`/`SheetLabel` carry one consistent voice across the command centre, setup wizard and profile.
3. **Domain rules are legible in the UI, not just in code.** Reglement clause numbers appear directly in forfeit/cancel copy shown to the director, closing the loop between rulebook and interface.

## Priority Issues

**[P0] The Oche Rule — the design system's own turn-indicator rule — is broken on the one screen it exists to serve.**
- **Why it matters**: `scoreboard-sides.tsx:55-63` renders both participants' remaining score at the same `text-display` size; only background tint and text color distinguish active from inactive. This is the single most safety-critical judgment a board scorer makes at speed, and the size gap that's supposed to make it instant is gone — it also violates the Never-Only-Colour rule, since color is now the *only* remaining signal. The detector independently flags `scoreboard-sides.tsx:51` (`text-slate-400 on bg-emerald-500`) as a contrast failure in the same file.
- **Fix**: Replace the hand-rolled `<p>` with `<Score size={isActive ? "display" : "lead"} tone={isActive ? "chalk" : "dim"}>` — this exact pattern is already implemented correctly one file over, in `board-wedge.tsx:146-151`.
- **Suggested command**: `/impeccable harden` (or `/impeccable polish` if bundled with the P1 below)

**[P1] Design system abandoned on the highest-traffic surfaces, reintroducing a banned third/fourth accent hue.**
- **Why it matters**: `match-scoreboard.tsx`, `scoreboard-status.tsx`, `scoreboard-header.tsx`, `dart-keypad.tsx`, `checkout-dialog.tsx`, all of `live-tournament.tsx`, `health-dashboard.tsx` and `app/offline/page.tsx` use raw `amber-*`/`rose-*`/`emerald-500`/`slate-9xx` instead of `.sektorenring` tokens — directly violating "no third accent hue" (amber shows up for pending/queued states in four files where `StateTag`'s existing `waiting` tone was built for exactly this). The detector's 11 contrast findings sit almost entirely inside this same set of files, so this isn't just an aesthetic drift — it's independently measurable as an accessibility regression (`members-route.tsx:306`, amber-500 again, is the 11th instance in an unrelated part of the app, suggesting the pattern has spread past the scoring surfaces).
- **Fix**: Route these components through `packages/ui`'s existing `Wedge`/`StateTag`/signal tokens instead of raw Tailwind palette classes; the tokens already carry contrast-correct lit/filled pairs, so this would also close all 11 detector findings.
- **Suggested command**: `/impeccable colorize` or `/impeccable polish`

**[P1] Alarm-priority content is buried under administrative chrome for the director.**
- **Why it matters**: In `command-centre.tsx`, render order is `PageNav → DashboardHeader → SharePanel → DisplayKeysPanel → [conflict/error banners] → queue → boards`. A version conflict or command error — exactly what a director needs to see and act on instantly during a live incident — renders below two share/display-key panels most directors never touch mid-tournament.
- **Fix**: Move conflict/error state to immediately below the header, or make it float/sticky.
- **Suggested command**: `/impeccable layout`

**[P2] First impression contradicts "authored for darts."**
- **Why it matters**: `application-dashboard.tsx:20-29` shows a full-weight raw infra health panel ("DartBase-Dienste: Web/API/Datenbank/Redis") beside the login form — a first-time visitor's very first view of the product is an ops dashboard, not anything dart-related.
- **Fix**: Demote to a single small `StateTag` pill, or move behind an ops-only route.
- **Suggested command**: `/impeccable distill`

**[P2] Cognitive-load chunking failures outside the legitimately dense command centre.**
- **Why it matters**: `player-profile.tsx:36-49` renders 8 stat tiles in one flat grid with no sub-grouping, on the one page explicitly meant to be calm rather than dense-by-design; `setup-sheet.tsx` section "1 · Turnier" bundles 8 fields ungrouped. Both fail the ≤4-items-per-group cognitive load check that the command centre is deliberately exempt from but these two surfaces are not.
- **Fix**: Split each into 2 labeled subgroups.
- **Suggested command**: `/impeccable layout`

**[P3] Help is orphaned from the tasks that need it.**
- **Why it matters**: `Bedienungsanleitung` is linked exactly once, from the anonymous landing page footer — never from the command centre, scoreboard, or encounter centre, i.e. absent from every screen where a confused first-timer (Jordan) actually needs it.
- **Fix**: Add a contextual help link/shortcut to the scoreboard and command-centre chrome.
- **Suggested command**: `/impeccable clarify`

Red flag: `live-tournament.tsx`'s `BracketSlotLine` (lines 282-296) distinguishes OPEN/LOSER states mostly by color/opacity — only WINNER gets an explicit mark, so a colorblind spectator following the bracket has less to go on than the Never-Only-Colour rule intends.
